# Ubuntu machine adaptations

This repository’s `ubuntu` output is a **standalone Home Manager** configuration.
It manages the `knirski` user environment, not the Ubuntu operating system.
Use this checklist for the Ubuntu machine (`LT43514`).

## Repository-side adaptations

These are already applied in this checkout:

- `modules/parts/ubuntu.nix` targets `knirski` and `/home/knirski`.
- The pinned Home Manager executable is available in the repository dev shell.
- The Ubuntu output imports the shared base, development, desktop, SSH, Sway,
  Dank Material Shell, Dank Calendar, Dank Search, and DMS plugin aspects.
- `pkgs.mesa` is in `home.packages` so the profile carries an EGL vendor for
  the `/run/opengl-driver` symlink described under "Required Ubuntu-level
  setup" below. Nothing is wrapped and no GL variables are exported.
- Desktop applications come from nixpkgs rather than snaps. Slack, VS Code and
  IntelliJ IDEA are declared in `modules/parts/ubuntu.nix`; Spotify and
  Bitwarden already arrive through `aspects.homeManager.desktop`. Once
  activated, remove the redundant snaps:

  ```bash
  sudo snap remove slack code intellij-idea spotify bitwarden
  ```

  This is not only tidiness. Snap-packaged Electron applications get their GL
  from inside the snap sandbox, which `/run/opengl-driver` cannot reach; the
  Slack snap starts but never maps a window under Sway for exactly that
  reason. See the comment in `modules/parts/ubuntu.nix`.
- The Sway background is a generated image
  (`modules/_pkgs/hive-grid-wallpaper.nix`), set through
  `wayland.windowManager.sway.config.output."*".bg`, so this machine is
  visually distinct from the other hosts. It is set on Sway's output rather
  than through the Dank Material Shell module, because that module's
  `settings` option replaces the whole of
  `~/.config/DankMaterialShell/settings.json` with a read-only store symlink
  and would stop the shell persisting any change made from its UI.
- `~/.local/bin/sway-ubuntu-session` is the session launcher GDM executes. It
  is generated by `modules/parts/ubuntu.nix` and does four things Home Manager
  cannot express as plain session variables:
  - **PATH.** GDM execs the script directly, so no login shell ever sources
    `~/.profile` or `hm-session-vars.sh`. Without this the inherited PATH is
    Ubuntu's system default and every Sway keybinding — which Sway runs
    through `sh -c` — fails with `ghostty: not found`.
  - **D-Bus.** It starts Sway on the session bus GDM already provides and only
    falls back to `dbus-run-session` when there is none, which is the bare
    virtual-console case. A second bus would hide the `systemd --user` manager
    behind a private socket: Sway's
    `dbus-update-activation-environment --systemd` would never reach it, so
    its `XDG_SESSION_TYPE` would stay stale and the `dms`/`dcal`
    `ConditionEnvironment` gates would keep skipping. It probes the socket at
    `$XDG_RUNTIME_DIR/bus` rather than `DBUS_SESSION_BUS_ADDRESS`, because
    Ubuntu exports that variable only from `/etc/X11/Xsession.d`.
  - **GPU selection.** It pins wlroots to the Intel iGPU, resolving
    `/dev/dri/by-path/pci-0000:00:02.0-card` to its `cardN` target at runtime.
    `cardN` indices follow driver probe order and are not stable, but
    `WLR_DRM_DEVICES` is colon-separated and the by-path name embeds the PCI
    address — passing it verbatim makes wlroots split it into three bogus
    paths and abort with `Found 0 GPUs`.
  - **Toolkit variables**, the standalone equivalent of the NixOS
    `sessionVariables` in `modules/nixos/sway.nix`.
- `dms` and `dcal` are wanted by `sway-session.target` as well as
  `graphical-session.target` (`modules/home/sway.nix`). systemd evaluates
  `ConditionEnvironment` once per start attempt, and
  `graphical-session.target` stays up once reached — so if anything reaches it
  before Sway has pushed `XDG_SESSION_TYPE` into the user manager (a crashed
  session attempt is enough), both units are recorded as skipped and never
  retried for the rest of the login. `sway-session.target` is started and
  stopped by Sway on every run, which guarantees a fresh attempt.
- Their `Service.Environment` sets `PATH` only, and only on Ubuntu: NixOS
  hosts inherit a correct PATH from `pam_env`, and overriding it there would
  drop `/run/current-system/sw/bin`, where `ddcutil` lives for DMS's DDC/CI
  brightness control.

The normal activation command is:

```bash
cd /home/knirski/repos/external/git/knirski/nix-config
nix develop '.#' -c home-manager switch --flake .#ubuntu -b backup
```

The `-b backup` flag is intentionally a **machine-local choice**. It preserves
an existing file that Home Manager needs to manage as `<file>.backup`. It does
not make backup behavior the default for other hosts or repository users.

The local wrapper at `~/.local/bin/hms-ubuntu` runs this same command. It is
machine-local and is not part of the repository.

## Machine-local environment secrets

This machine keeps its private shell environment in `~/.envvars`. It is not
part of the repository and must not be copied into the Nix store or committed:

```bash
chmod 600 ~/.envvars
source ~/.envvars
```

The file is shell input and may contain functions as well as exported
variables. The shared Home Manager zsh configuration now conditionally sources
it, so the variables are available in every new zsh terminal without embedding
their values in the Nix store:

```zsh
if [[ -r "$HOME/.envvars" ]]; then
  source "$HOME/.envvars"
fi
```

Do not print the values when testing. Check only that required names are set,
for example:

```zsh
echo "${GITLAB_TOKEN:+GITLAB_TOKEN is set}"
```

## Required Ubuntu-level setup

Home Manager cannot install or configure these system-level components:

1. **Nix**

   Install Nix with the Determinate installer, then ensure flakes work:

   ```bash
   nix --version
   nix eval nixpkgs#lib.version --raw
   ```

2. **Graphics driver**

   Install the driver using Ubuntu’s mechanism. Intel and AMD systems normally
   use Ubuntu’s Mesa packages, which is the case here: `LT43514` drives every
   connector from the Intel iGPU and needs no NVIDIA userspace (see step 5).
   For a machine that does need it:

   ```bash
   ubuntu-drivers autoinstall
   ```

   This covers Ubuntu’s own programs only. Nix programs get their GL from
   step 6 and are unaffected by what is installed here.

3. **D-Bus user session**

   Required when starting Sway from a console:

   ```bash
   sudo apt install dbus-user-session
   ```

4. **XDG portal packages**

   The standalone Home Manager Sway aspect provides no portal:

   ```bash
   sudo apt install xdg-desktop-portal xdg-desktop-portal-gtk xdg-desktop-portal-wlr
   ```

   `gtk` is required, not optional — see step 7 for which backend serves what.
   Ubuntu Desktop installs `xdg-desktop-portal-gnome` too; leave it, it is
   `UseIn=gnome` and therefore inert in a Sway session.

   No separate Polkit agent is needed: DankMaterialShell registers its own
   (`PolkitService` in its log). Install one only if running Sway without DMS.

5. **GDM must run Wayland**

   Ubuntu ships `/etc/gdm3/custom.conf` with `WaylandEnable=false`, which keeps
   the greeter on Xorg. That Xorg server holds DRM master, so a Wayland session
   started from it cannot page-flip. Sway comes up but never displays, logging
   `Atomic commit failed: Device or resource busy` for every connector.

   Comment the line out and restart the display manager:

   ```bash
   sudo sed -i 's/^WaylandEnable=false/#WaylandEnable=false/' /etc/gdm3/custom.conf
   sudo systemctl restart gdm3
   ```

   Nothing else forces Xorg on this machine: no NVIDIA kernel module is loaded
   and the kernel command line has no `nomodeset`, so `61-gdm.rules` does not
   apply. Every connector (`eDP-1`, `DP-1`–`DP-4`, `HDMI-A-1`) hangs off the
   Intel iGPU; the discrete RTX A1000 is a bare `3D controller` with no display
   outputs and is not needed for the session.

6. **OpenGL for Nix programs (`/run/opengl-driver`)**

   Nixpkgs patches libglvnd to look for an EGL vendor in
   `/run/opengl-driver/share/glvnd/egl_vendor.d` before `/etc/glvnd` and
   `/usr/share/glvnd`. On Ubuntu only the last exists, and its
   `libEGL_mesa.so.0` cannot be dlopened from a Nix-glibc process — it needs
   Ubuntu's `libgallium-*.so`, which a Nix binary cannot resolve. Every Nix GL
   program therefore fails with `Failed to create EGL display`; Qt words it as
   `EGL not available`.

   Point `/run/opengl-driver` at the Home Manager profile, which carries
   `pkgs.mesa`. `/run` is a tmpfs, so it needs a tmpfiles rule:

   ```bash
   sudo tee /etc/tmpfiles.d/nix-opengl-driver.conf >/dev/null <<'EOF'
   L+ /run/opengl-driver - - - - /home/knirski/.nix-profile
   EOF
   sudo systemd-tmpfiles --create /etc/tmpfiles.d/nix-opengl-driver.conf
   ```

   Ubuntu's own libglvnd has no `/run/opengl-driver` in its search path, so
   this is invisible to Ubuntu binaries. mesa's vendor JSON carries an
   absolute `library_path` and mesa's RUNPATH resolves its own dependencies,
   so no `LD_LIBRARY_PATH` is involved.

   The symlink targets the profile rather than a store path: the profile is a
   GC root and follows every generation, so mesa upgrades cannot leave it
   dangling.

   This is deliberately a single system-level symlink rather than nixGL
   wrappers. Wrapping the compositor only covers processes Sway spawns —
   `systemd --user` units and D-Bus-activated services (DankMaterialShell,
   Dank Calendar, Ghostty's `app-com.mitchellh.ghostty.service`) are not Sway
   children and each needed a separate fix. The symlink covers every Nix
   process regardless of what started it.

7. **XDG desktop portal backend**

   `wlr.portal` is `UseIn=…;sway;…` but implements only `Screenshot` and
   `ScreenCast`. `Settings`, `FileChooser` and the rest live in `gtk.portal`
   and `gnome.portal`, both `UseIn=gnome`, so a Sway session gets no `Settings`
   backend at all. `xdg-desktop-portal` then answers every read with
   `Failed to ReadAll() from Settings implementation: Timeout was reached`, and
   GTK4/libadwaita clients block on that during startup — Ghostty hangs before
   mapping a window, while non-GTK terminals such as `foot` are unaffected.

   Home Manager writes `~/.config/xdg-desktop-portal/sway-portals.conf` naming
   the backends explicitly, so no apt changes are needed. `default=wlr` is not
   an option: it would leave every interface except those two unimplemented.

   DankMaterialShell's clipboard does not use portals — it speaks
   `wlr-data-control` directly (see `modules/home/sway.nix`), so the GTK
   default does not affect it.

8. **Sway login session**

   Home Manager installs Sway and its configuration, but GDM only discovers
   session files in `/usr/share/wayland-sessions`. Create the system entry once:

   ```bash
   sudo install -D -m 0644 /dev/stdin \
     /usr/share/wayland-sessions/sway-nix.desktop <<'EOF'
   [Desktop Entry]
   Name=Sway (Nix, Home Manager)
   Comment=Tiling Wayland compositor managed by Home Manager
   Exec=/home/knirski/.local/bin/sway-ubuntu-session
   Type=Application
   EOF
   ```

   After logging out or restarting GDM, select **Sway (Nix, Home Manager)**.
   The fallback is a virtual console (`Ctrl+Alt+F3`), followed by the same
   script. It notices that a console login has no D-Bus session bus and starts
   one itself:

   ```bash
   ~/.local/bin/sway-ubuntu-session
   ```

## Optional Ubuntu-level setup

### Make Nix zsh the login shell

Home Manager configures zsh but cannot edit `/etc/passwd` or `/etc/shells`.
If desired:

```bash
sudo sh -c 'echo "/home/knirski/.nix-profile/bin/zsh" >> /etc/shells'
chsh -s "$HOME/.nix-profile/bin/zsh"
```

Log out and back in afterward.

### Tailscale

Install and operate Tailscale through Ubuntu’s package or GUI mechanism. The
Home Manager SSH aspect only configures SSH client behavior; it does not run a
Tailscale daemon on standalone Ubuntu.

### GitHub CLI authentication

Authenticate `gh` separately using a GitHub token with the required scopes:

```bash
gh auth login
```

### PATH for the local wrapper

If `~/.local/bin` is not already on `PATH`:

```bash
export PATH="$HOME/.local/bin:$PATH"
```

## What starts with Sway

After Home Manager activation and a Sway login, the configuration enables:

- Sway and its keybindings;
- Dank Material Shell through its systemd user service;
- Dank Calendar through its systemd user service;
- the media playback sleep inhibitor;
- DMS IPC commands used by the Sway keybindings.

Check the user services after login:

```bash
systemctl --user status dms.service dcal.service
```

## What remains outside this configuration

Standalone Home Manager does not manage Ubuntu updates, kernel settings, GPU
drivers, display-manager configuration, system services, `/persist`,
restic/btrbk backups, or NixOS-only aspects such as gaming.

Three items are system-level and must be reapplied by hand if this machine is
rebuilt — none of them is captured by a Home Manager generation:

| File | Purpose | Step |
| --- | --- | --- |
| `/etc/gdm3/custom.conf` | `WaylandEnable=false` commented out | 5 |
| `/etc/tmpfiles.d/nix-opengl-driver.conf` | `/run/opengl-driver` symlink | 6 |
| `/usr/share/wayland-sessions/sway-nix.desktop` | GDM session entry | 8 |

Portal *selection* is now Home Manager's (step 7), but the portal *packages*
and the Polkit agent remain Ubuntu's.

For the initial installation walkthrough, see
[`docs/install-ubuntu.md`](install-ubuntu.md). For standalone Home Manager
semantics, see the [Home Manager manual](https://nix-community.github.io/home-manager/).
